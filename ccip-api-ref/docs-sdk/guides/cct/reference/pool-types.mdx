# CCT pool types and version support

The EVM CCT operations work with several token pool contract types across four pool versions (v1.5.0, v1.5.1, v1.6.1, and v2.0.0). What the SDK can *deploy* is narrower than what it can *administer and read*: new pools are always v2.0.0, while the read and configuration operations recognize older pools too. Use these matrices to pick a deployable type and to check whether an operation applies to a given pool.

## Deployable and recognized pool types

`deployTokenPool` and the [TokenPoolFactory](../evm#alternative-deploy-via-tokenpoolfactory) deploy v2.0.0 pools only. The read and administration operations recognize all seven pool types across every supported version.

| Pool type | `deployTokenPool` | Factory | Administer / read |
| --- | --- | --- | --- |
| `BurnMintTokenPool` | Yes (v2.0.0) | Yes (v2.0.0) | v1.5.0 to v2.0.0 |
| `BurnFromMintTokenPool` | Yes (v2.0.0) | No | v1.5.0 to v2.0.0 |
| `BurnWithFromMintTokenPool` | Yes (v2.0.0) | No | v1.5.0 to v2.0.0 |
| `LockReleaseTokenPool` | Yes (v2.0.0) | Yes (v2.0.0) | v1.5.0 to v2.0.0 |
| `BurnToAddressTokenPool` | No | No | v1.5.0 to v2.0.0 |
| `BurnMintWithLockReleaseFlagTokenPool` | No | No | v1.5.0 to v2.0.0 |
| `SiloedLockReleaseTokenPool` | No | No | v1.5.0 to v2.0.0 |

## Operation applicability by pool version

A v2.0.0-only operation throws `CCTOperationUnsupportedError` when the resolved pool is older, and the sender allowlist exists only through v1.6.1. Read the pool version (`getTokenPoolState`) before calling a version-scoped operation.

| Operation group | Methods | Applies to |
| --- | --- | --- |
| Remote lanes | `applyChainUpdates` | All versions (declare the matching `version` shape) |
| Rate limits | `setChainRateLimiterConfigs` | All versions (`fastFinality` targets the v2.0.0 FTF bucket only) |
| Admin & pool registration | `registerAdmin`, `acceptAdmin`, `setPool`, ownership transfers | All versions |
| Reads | `getTokenPoolState`, `getTokenPoolRemotes`, `getTokenAdminRegistry` | All versions |
| Sender allowlist | `applyAllowlistUpdates` | v1.5.0 to v1.6.1 only (removed in v2.0.0) |
| Transfer fees & finality | `applyTokenTransferFeeConfigUpdates`, `setAllowedFinalityConfig`, `getFee`, `getTokenTransferFeeConfig`, `getAllowedFinalityConfig` | v2.0.0 only |
| CCVs & hooks | `applyCCVConfigUpdates`, `getCCVConfig`, `getAllCCVConfigs`, `getRequiredCCVs`, `deployAdvancedPoolHooks`, `updateAdvancedPoolHooks`, `getAdvancedPoolHooks` | v2.0.0 only |
| Lockbox | `getLockbox` | v2.0.0 only |

### Solana

Solana has one burn-mint program and one lock-release program, with no type-and-version matrix. Both are pinned to the `solana-v1.6.4` release tag.

- burn-mint (`poolType: 'burn-mint'`): [burnmint-token-pool](https://github.com/smartcontractkit/chainlink-ccip/tree/c73892d4d33926195eee87b77013883e650a833c/chains/solana/contracts/programs/burnmint-token-pool)
- lock-release (`poolType: 'lock-release'`): [lockrelease-token-pool](https://github.com/smartcontractkit/chainlink-ccip/tree/c73892d4d33926195eee87b77013883e650a833c/chains/solana/contracts/programs/lockrelease-token-pool)
